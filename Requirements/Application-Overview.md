# Application Overview: Automation Exercise

## 1. Application Name
Automation Exercise (https://automationexercise.com/)

## 2. Type of Application
B2C E-commerce web application (online clothing store)

## 3. Purpose
"Let user browse products and buy clothes without going to a physical store."

## 4. Target users
- Guest user: can browse products and add to cart but no checkout allowed.
- Registered user: can browse products and add to cart and can checkout. 
- No admin role is visible or accessible from public site.

## 5. Main features
Account sign up, account login, search products, filter products by brand and category, view product details, add products to cart, checkout, remove items from cart ,place order and payment, download invoice, delete account , write reviews ,  contact us form, newsletter subscription, account logout.

## 6. The main user journey
- Returning user:  Login-> Browse -> View product -> Add to cart-> Checkout->Place order-> Pay and confirm order->Download invoice-> Logout.
- New user:  Signup-> Browse -> View product -> Add to cart-> Checkout->Place order-> Pay and confirm order-> Download invoice-> Logout.
- Other flows (optional): Search, filter by category/brand, write a review, contact us, subscribe to newsletter

## 7. Questions
### Clarifying Questions
- How will we decide which items are going to be listed as recommended items?
- What should happen when a product is out of stock? 
- Is there a limit of product items a customer can purchase? 
- What are the rules for password(maximum/ minimum length, required special characters)? 
- What should happen if the customer sign up with an email that is already registered?
- Should a customer able to reset a forgetten password?
### Suggestions
- Customers should be able to add their card info in their profile instead of filling the card info every time users try to checkout.
- Customers should be able to get access to their placed orders.
