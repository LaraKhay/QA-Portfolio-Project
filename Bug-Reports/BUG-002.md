# BUG-002: Live site shows Django debug page revealing internal URLs after paying with a negative total

| Field | Details |
|---|---|
| **Reported by / Date** | Lara / 2026-10-13 |
| **Environment** | macOS Tahoe 26.5.2, Google Chrome 155.0.8059.12 (arm64), https://automationexercise.com |
| **Module** | Checkout and Payment |
| **Related** | TC-CART-13b, OBS-13, BUG-001 |
| **Severity** | High — Debug mode is enabled on the live site, revealing the framework and all 33 internal URLs (including admin/), which helps attackers plan attacks. Only the site structure was exposed here, but debug mode can reveal more sensitive details (code, settings) on other errors. |
| **Priority** | High — It is a security misconfiguration on the live site that any visitor can reach, and the fix (turning off debug mode) is a single setting. |
| **Reproducibility** | Always (3 of 3 attempts with quantity -3) |
| **Status** | New |

## Preconditions
1. The user is logged in with ACC-01.
2. The cart contains Men Tshirt with Quantity -3 (Total Rs. -1200), added as described in BUG-001.

## Steps to Reproduce
1. Click **Cart** in the header.
2. Click **Proceed To Checkout**.
3. Click **Place Order**.
4. Fill in the payment fields using PAY-VALID.
5. Click **Pay and Confirm Order**.

## Expected Result
- After step 5: a simple, user-friendly error page is displayed that does not reveal any internal information. Debug mode is turned off on the live site.

## Actual Result
- After step 5: the browser opened https://automationexercise.com/payment_done/-1200 and displayed a "Page not found (404)" developer debug page. The page revealed:
  - The web framework used: Django
  - That debug mode is enabled: "You're seeing this error because you have DEBUG = True in your Django settings file."
  - The full list of 33 internal URL patterns, including "admin/", "payment_done/<int:overall_amount>", "download_invoice/<int:overall_amount>", and all API endpoints

## Additional Information
- **How the page was reached:** the negative total comes from BUG-001. The URL pattern "payment_done/<int:overall_amount>" only accepts positive numbers, so "-1200" matched no page and triggered the error.
- **Why this is a separate bug:** fixing BUG-001 would remove this particular path, but debug mode would still be enabled. Any other error on the site could still show a debug page, so turning off debug mode is a separate fix.
- **Hypothesis (not tested):** the URL patterns show that the order amount is passed in the web address ("payment_done/<int:overall_amount>" and "download_invoice/<int:overall_amount>"). If the invoice amount is taken from the URL, someone could change the number in the address to produce an invoice for a different amount. This was deliberately not tested, to avoid tampering with the site.
